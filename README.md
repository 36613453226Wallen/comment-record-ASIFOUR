# 对话记录

这类对话的价值不在「谁说了哪句话」，而在两件事有没有被分开写清楚：

1. **我的个人情况**：处境、约束、当时的判断
2. **对方给出的经验**：他们经历过什么、据此给了什么建议、建议在什么条件下才成立

## 建议用什么

**用 Markdown 写「结构化谈话纪要」，不要用逐字稿、标准会议纪要，也不要用 Word。**

| 形式 | 适不适合这次对话 | 原因 |
| --- | --- | --- |
| **结构化谈话纪要（采用）** | 适合 | 把「情况 / 经验 / 建议 / 取舍 / 行动」拆开，事后能复查、能执行 |
| 逐字聊天记录 | 不适合当主文档 | 个人情况和建议缠在一起，很难回头提取可复用经验 |
| 标准会议纪要 | 不适合 | 适合决议和待办，不适合经验转译 |
| 日记或感想 | 不够 | 容易只留下情绪，丢掉对方经验的适用条件 |
| Word / 网页长文 | 不优先 | 不方便在仓库里对比修改，也不方便以后补记 |

文件用 Markdown，是因为它能进 Git、能 diff、能继续补一版「事后复盘」。

## 怎么记

每场谈话一份文件，放在 [`records/`](records/)。复制 [`templates/谈话纪要.md`](templates/谈话纪要.md)，按下面六段写：

1. **谈话目的**：为什么要谈，当时想解决什么
2. **个人情况**：只写事实、约束、自己的判断，不把对方的话写进来
3. **对方经验**：尽量保留原话或可核对的经历，写清当时怎么处理、结果如何
4. **对方建议**：每条都带「依据」和「适用条件」，避免把别人的路径直接当成自己的答案
5. **我的理解与取舍**：采纳 / 暂缓 / 不适用，以及原因
6. **下一步**：可执行的行动、时间、还要再确认的问题

关键原话放到附录，不要让整篇变成聊天截图。
